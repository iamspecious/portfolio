## Fixed on this branch

### F1. Bootstrap replaced with a 14 KB subset and a few lines of tab code *(performance)*
The page used about 4% of Bootstrap's stylesheet, and its only use of Bootstrap's script was switching tabs. Both came from a CDN as `5.3.0-alpha1`, a pre-release. Now:
- `vendor/bootstrap-subset.css` holds only the rules the page uses, generated with PurgeCSS from the same Bootstrap version so nothing changes visually. The runbook explains how to regenerate it.
- Tabs are handled in `index.html`: click, arrow keys, Home/End, `aria-selected`, `aria-controls`, and a `tabshown` event that Digital Spec, search and shared links wait on before scrolling. The smoke test checks keyboard navigation.
- All 16 screenshots (5 tabs, Digital Spec open, a lane result and search results, at desktop and phone widths) are pixel-identical before and after.

### F2. The portfolio index downloaded twice *(performance)*
Digital Spec and search each fetched `portfolio-index.json` (64 KB raw). They now share one request.

### F3. The page jumped 41px when the search bar appeared *(performance, layout shift)*
The header now reserves the bar's height before the script fills it. Page-content layout shift went from 0.02 to 0.

### F4. Digital Spec would send `advisory-` cards to the wrong tab *(bug, latent)*
Digital Spec guessed each item's tab from its id prefix (`work-`, `cs-`, otherwise Projects), so the new `#advisory-…` case studies would have opened the Projects tab. It hasn't happened yet because no lane shows them (see D1). Routing now looks up which tab actually contains the item, so any future prefix works.

### F5. Two copies of the sort code *(code size)*
The Case Studies sort was a copy of the Projects sort. One function now serves both, each sort control sorting its own tab.

### F6. README out of date *(fitting)*
It said "Four narrative case studies"; the page has 14. The Case Studies section now lists all four narrative and ten advisory cases. The Stack section mentions the Bootstrap subset.

### F7. "Advisory" badge contrast *(accessibility)*
Grey on dark grey at 3.96:1; lightened to 6.2:1.

### F8. Small consistency fixes
- Stamped and Learnovate case studies sorted by year-end placeholders (`2020-12`, `2017-12`). They now use their real end dates from the index; the order is unchanged.
- `audit.py` rejected the advisory cases' capitalised keywords ("EOR", "GDPR"). Search ignores case, so the rule was stricter than needed. It now only requires non-empty strings.

### Tooling
- `audit.py` §9 **Page weight**: gzip size per file with budgets (`index.html` 160 KB, index 25 KB), any third-party file on the page, the shared index request, and element count. These are reported every run, so growth shows up early.
- `audit.py`: Case Studies tab checks (sort dates against the index, every card inside a sortable block) and README checks for every case study.
- `smoke-test.js`: both tabs' sorts, keyboard tabs, an advisory shared link; the Bootstrap workaround is gone.
- `search-lexicon.json`: expected search words for the 10 advisory cases. All 177 words find their item.

The dialogue panel is centred on screen, so when the answer buttons appear after each message it grows and shifts upward by half the growth. That's the only remaining layout shift (0.036, within the "good" range of under 0.1). Anchoring the panel near the top of the screen would stop it moving; it would also sit a little higher than it does now.

## Performance: what's left, and why it stays

- **`index.html` is 123 KB gzip**, and 62% of it is the Projects tab, mostly dev logs (335 entries). The dev logs are the portfolio's point, and having them in the page keeps them searchable with Ctrl+F and by search engines. Older entries are already hidden behind "show older entries", which costs the browser nothing until opened. The 160 KB budget in `audit.py` will warn before this becomes a problem.
- **Opening the Projects tab takes ~0.55 s on a 4×-slowed CPU** (instant on a normal one). The usual fix, telling the browser to skip off-screen cards, would bring back the deep-link landing problem fixed on 2026-10-16, so it isn't worth it at this size.
- **Search** costs about 25 ms per keystroke on a slowed CPU across 59 items, well under what anyone would notice.
