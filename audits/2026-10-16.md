## Fixed on this branch

### F1. Deep links into the Projects tab landed ~700px short *(high)*
Every Digital Spec card and search result pointing at a Projects-tab item scrolled to the wrong place. Cause: the Tarot Machine contact sheet (added 2026-10-15) is a lazy-loaded image with no `width`/`height`. Tarot sorts first in the tab, so the image loaded mid-scroll and pushed everything below it down by its full height. **Fix:** `width="666" height="2000"` on the `<img>`. The browser now reserves the space up front, and the CSS still scales it to 240px. Dev log entry added on the Digital Spec card.

### F2. Portfolio Search returned noise and buried exact matches *(high)*
- The code comment said every query word must match, but the code kept any item matching *one* word. "support engineer" returned 33 results.
- Results were always grouped Projects, then Documents, Case Studies, Work. A search for a job title put the job last: "chief of staff" ranked both Chief of Staff roles below 12 projects, and "Fractional Chief of Staff — Spec Solutions" ranked #28.
- Substring matching: "EOR" matched "th**eor**y" and put the KH Lore Checker first; "spec" matched LoreBySpec.
- Searching anything with `&` broke the highlighting and showed `&amp;` in titles (e.g. "KH Title &amp;amp; Thumbnail Audit").

**Fix (`portfolio-search.js`):** a query word must start a word in the title, tags or summary. Every word must match, and partial matches show only when nothing matches all of them. Groups are ordered by their best result. Highlighting escapes each piece separately. Results now: "chief of staff" gives 2 results (both roles), "support engineer" gives 6, "EOR" gives 3 (all EOR work). Dev log entry added on the Portfolio Search card.

### F3. "Live on this site" badges linked to the domain root *(medium)*
On Portfolio Search and Digital Spec, `href="/"` opened `iamspecious.github.io/` in a new tab. That's outside the `/portfolio/` site, so on GitHub Pages it's a 404 unless a user site exists. **Fix:** in-page links to the search bar (`#pfs-root`) and the top of the page (`#fd-root`), with no new tab.

### F4. README out of date *(medium)*
Six Projects-tab items had no README row: HR Webhook Integration Layer, Role-Fit Evaluator, KH Description Optimizer, YouTube A/B Testing Tool, KH Title & Thumbnail Audit, PostHog First-Run Audit. Other problems: the filter list named 4 categories (there are 8); "FAQ / Knowledge Base Chatbot" didn't match the card title; the Tarot row repeated itself; the Stack section said "no server" for everything, missing the Cloudflare Worker proxy, Sonnet 4.6, PostHog analytics, and the Python, Docker and firmware projects. **Fix:** all corrected. Added a "How the site fits together" section (what each file does, how to add a project) and an "Auditing" section.

### F5. Pins with no recorded reason *(low)*
`portfolio-search` and `proj-digital-spec-front-door` carry `audiencePin: ["builder-technical"]` with empty `notes`, which TAXONOMY §11 forbids. **Fix:** rationale written into `notes` (from the 2026-09-03 routing audit, #42).

### F6. Stale audit docs *(low)*
`ROUTING-MAP-DIAGNOSTIC.md` still says `audienceExclude`/`audiencePin` aren't implemented (fixed 2026-06-21) and describes 38 items. It now has a "historical" banner. `TAGGING-AUDIT.md` has an addendum pointing here.

### D6. Search lexicon: add a `keywords` field
**Applied:** `keywords` on 24 projects and documents, searched at tag weight, documented in TAXONOMY.md §13 and validated by `audit.py`. All 157 lexicon words now find their item. One expectation was dropped ("accessibility" for Digital Spec, which the card doesn't claim).
Search reads only title, summary and tags. The tech tags printed on each card ("Jira", "Slack", "HiBob", "M5Stack"…) are not searchable, so a visitor can see a word on a card, search for it, and get nothing. The synonym map can't fix this, because it maps words to tags rather than to items, and it can't handle phrases like "Kingdom Hearts". Proposal: an optional `keywords` array per index item (search-only, not a facet, so the taxonomy stays clean), scored like a tag. Suggested words are in the per-item table below. Every one is a current miss from `tools/search-lexicon.json`.

### D7. Shareable links and back links
**Applied:** `index.html#<tab or item id>` opens the tab and jumps to the item, and Digital Spec docks instead of covering it. The address bar follows tab changes, search results and Digital Spec cards, so what's on screen can be copied and shared. Every tool and document page's back link now returns to its own card.
`index.html` ignores the URL hash, so `index.html#projects` (PregVoice's back link) opens the About tab, and no project can be linked to directly. Every tool's "back to portfolio" link also returns to About. A ~15-line hash handler (switch to the tab containing `#id`, then scroll) would make every card linkable, e.g. `…/portfolio/#proj-tarot-machine`. Back links could then return to the card.

### D8. Link previews and search engines

Case studies, AI tools, writing samples and build logs."*
